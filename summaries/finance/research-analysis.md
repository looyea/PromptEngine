# 金融投研与分析提示词

> 一级类：F 金融 · 二级：数据分析 + 工作流
> 素材：`素材/github/awesome-claude-finance-prompts/`（**许可证未声明**，README + 16 章 × 8 = 128 条机构级模板；已通读 README、第 1/16 章全文并抽样第 2/3/4/5/6/11/14 章代表条目，全部 128 条标题已聚类）
> 用途：引擎组装金融投研类提示词的结构原料与合规条款。**因素材未声明许可证，本篇全部为归纳改写，不搬运原文；引擎组装时同样只可改写复用其结构与方法，不得逐字复制原 prompt。** 所有输出为通用分析框架，非投资建议，须经合格分析师复核。

## 1. 概述

这是一套"机构投研台"式提示词库：前 11 章按业务台分组（股票研究/估值并购/宏观风险/财报情报/组合策略/量化交易/战略咨询/捐赠基金/主权财富/ESG 气候/固收信用），后 5 章是平台工程与提示词方法论（Claude 模型选型/Claude.ai 项目/量化代码/Cowork 插件/Masterclass）。README 开宗明义：**所有 prompt 都是通用分析框架，不产生实时数据；任何 AI 输出在任何专业场景使用前都必须经合格分析师复核**。

128 条模板共享一套"机构纪律"，这是本库最值得引擎吸收的东西：

- **CRAFT 五要素**（Context/Role/Action/Format/Tone）+ 四级成熟度演进；
- **BCE 纪律**：只给 Base Case Estimates，牛熊情景单列，禁止把乐观假设混进基准；
- **Assumption Log + 来源锚定**：每个关键假设标注来源与日期（无风险利率注明出处+日期、ERP 用 Damodaran、beta 附 R²）；
- **可证伪性**：投资论点必须附失效条件（invalidating conditions）、统计形态必须给经济学解释；
- **决策矩阵化**：输出落到 BUY/HOLD/AVOID、加仓/减仓/清仓等离散决策，附触发阈值；
- **方法论锚定**：Graham/Lynch/Buffett/Dalio/Swensen/AQR 等具名框架作为推理脚手架，而非让模型自由发挥。

### 2.2 单条模板的通用解剖

```
Role（具名方法论传承的分析师角色）
→ Task（分析动作 + 输入 [PLACEHOLDERS]：ticker/财报/数据表，全部占位符化）
→ Output Format（分节硬结构 + 📊 Excel Model Structure 工作表/行列布局 + 💡 Sample Output 示意）
→ 纪律条款（BCE/Assumption Log/来源日期/失效条件/决策矩阵）
→ 免责声明（通用框架+需合格分析师复核）
```
部分条目带虚构"Character notes"（人物小传）——是叙事化角色装置，不是真实人物或数据，改写时剥离。

### 2.3 CRAFT 四级成熟度（ch16 P1）

L1 只有 Action（"分析这只股票"）→ L2 +Role/Format → L3 +Context（数据/约束/受众）→ L4 +Tone+纪律条款+few-shot 锚定。引擎组装 F 类默认直达 L4。

### 2.4 推理与质检模式

- **CoT 宏观传导五步**（ch16 P2）：冲击事件 → 一阶传导（利率/汇率/商品）→ 二阶（行业盈利/信用）→ 组合映射 → 行动与对冲，每步显式写出机制。
- **Pre-mortem 四视角**（ch16 P3）：多头自辩 / 空头机制化路径（须给出 25-35% 损失的具体传导链）/ 风险经理（限额/流动性/相关性）/ 受托人（客户利益冲突），最后合成"论点存活条件"。
- **QC 协议**（ch16 P7）：数字溯源、假设一致性、前后期口径一致、结论与证据强度匹配。
- **决策矩阵**：财报前简报对 3 个 thesis-critical KPI 各设 beat/miss 阈值 → 对应加仓/持有/减仓动作；信用备忘录落到 BUY/HOLD/AVOID + Z-spread tight/fair/cheap 判断。
- **交易计划硬约束**（ch6 P8）：论点 ≤3 句；entry/stop/T1/T2 全给；R:R < 2:1 必须标旗拒绝；3 个 KPI 证实/证伪；强制退出条件（时间止损/论点失效/组合限额）。
- **量化代码纪律**（ch14）：docstring 写 WHY 不只写 WHAT；关键函数配单元测试；参数显式（如 VaR：10k 次模拟/252 日/Cholesky 相关/Student-t 肥尾/VaR95+99/CVaR）。
- **统计形态须有经济学解释**（ch1/ch6 异象类）：先问"为什么这个 edge 会存在、谁在亏钱"，再谈显著性，防数据挖掘偏差。

## 5. 差异与注意点

- **许可证未声明（最高优先）**：仓库无 LICENSE，默认版权保留。引擎与本篇一律**只吸收结构/方法/纪律并改写**，不逐字复制原 prompt、不搬运 Sample Output 原文；对外分发时注明方法论参考来源。虚构"Character notes"是叙事装置，改写时剥离，不得当作真实人物/机构背书。
- **无实时数据**：128 条全部依赖 [PLACEHOLDERS] 输入；模型自带的"记忆行情/财务数据"一律视为过期，组装时必须要求用户提供数据并标注 as-of date。ch13/15 的 Deep Research/MCP 数据连接（FactSet/LSEG/PitchBook）是平台能力描述，本引擎不默认具备。
- **平台绑定章节**：ch12-15（32 条）深度绑定 Claude 模型族/Claude.ai 项目/Claude Code/Cowork 插件，跨平台使用时只迁移其工作流思想（模型分工/成本分层/长上下文管理），不迁移产品操作细节。
- **BCE 与来源纪律不可省**：这是本库区别于普通"股票分析 prompt"的核心；引擎 QC 门对 F 类增加三查——假设日志是否齐全、基准是否混入乐观情景、结论是否附失效条件。
- **美国/机构语境本地化**：GIPS/Solvency II/SFDR/TCFD/401k 式 IPS 为欧美制度；A 股场景需替换披露口径（交易所公告/巨潮）、涨跌停与 T+1 约束、适当性管理（《证券期货投资者适当性管理办法》）、投顾牌照边界（无牌照不得输出个性化买卖建议）。
- **与 ENGINE.md 对接**：F 类高合规档，第 5 步注入 4.0 块；推理技法优先 CoT 五步/pre-mortem/决策矩阵（§2.4）；Loop 模式用于"数据采集→分析→质检→备忘录"多阶段交付。
- 素材中历史压力情景数字（2008 -38%、2022 股 -18%/债 -13% 等）为示例量级，改写使用时须核对真实指数口径。

## 6. 缺口

- **中国市场素材为零**：无 A 股/港股披露口径、财报准则（CAS vs GAAP）、北向/两融、中国宏观指标（社融/PMI 口径）模板，需另采或本地化改写。
- **个人理财/零售侧缺失**：全部为机构视角；退休规划、家庭资产负债、保险配置等零售场景未覆盖（ch8/9 的家族办公室条目最接近但门槛极高）。
- 无评测数据：128 条均无输出质量基准或回测验证，Sample Output 为示意性虚构。
- 实时数据管线（MCP 连接器配置、数据清洗调度）只有描述性 prompt，无可运行代码。
- 合规科技（RegTech）侧薄弱：反洗钱、交易监控、监管报送类模板缺失。
- 中文金融语料（研报语体、公告解析）未覆盖；本篇骨架输出语言需引擎按用户语言切换。
