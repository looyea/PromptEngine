# 平台档案：LAMP-PHP（Linux + Apache/Nginx + MySQL + PHP）

> ⚠️ **引擎自补知识（非收集素材），关键约束以官方文档为准，使用前核实。** 库内 PHP 素材为零——本档案全部平台约束为引擎自补；可引用的只有通用工程纪律与问卷结构（引擎/套餐/商城开发.md、引擎/问卷/编程-通用开发.md、汇总/软件开发/编码规约.md），逐条标注，不冒充 PHP 素材出处。
> 用途：问卷选项背后的约束层。被引用方：商城开发.md 技术组"Web"选项的传统栈分支、编程-通用开发.md Q3 stack 槽位；B4 方案 [人办] 清单供料（引擎/方案模板.md §3）。

## 1. 定位与适用场景

预算低、只有虚拟主机/共享主机、要维护遗留 PHP 系统、或想吃 WordPress/WooCommerce 生态（主题插件现成）时选它。需要现代前端体验（SSR/流式渲染）、长驻进程/队列/实时推送、或团队全 JS 技术栈时不选——转 Next.js 路线。它是"部署环境决定技术上限"的典型：主机能力先于框架选型确认。

## 2. 硬约束清单

| # | 约束 | 影响 | 来源 |
|---|---|---|---|
| L1 | PHP 版本与扩展必须先确认：7.x 已停止安全维护，新项目用受支持的 8.x；pdo_mysql/mysqli/mbstring/openssl 等扩展共享主机未必全开 | 版本决定可用语法与依赖库；生成代码前锁定版本号写进上下文卡 | 官方文档常识（自补；EOL 时间线易过时） |
| L2 | 共享主机通常无 shell/SSH，composer 受限或不可用；无 systemd/supervisor，跑不了队列 worker 与常驻进程 | 依赖要么本地 composer 装好连 vendor 上传，要么纯原生 PHP；异步任务退化为 cron 或请求内同步 | 官方文档常识（自补，逐主机商核实） |
| L3 | MySQL 版本方言：5.7 与 8.0 在窗口函数、CTE、默认认证插件（caching_sha2_password 致旧版 PHP 客户端连接失败）、保留字上有差异 | schema.sql 生成前锁定 MySQL 版本；统一 utf8mb4 | 官方文档常识（自补） |
| L4 | 会话与文件上传是 PHP 高频漏洞面：上传目录须禁脚本执行、扩展名+MIME 白名单、重命名存储；session 固定/劫持防护、登录态再生成 session id | 安全条款必须显式注入提示词——⚠️ 库内无成体系安全编码规约（汇总/软件开发/编码规约.md §6 明确缺口），本条按通用边界拼装，非现成素材 | 官方文档常识（自补）；缺口声明出自 汇总/软件开发/编码规约.md §6 |
| L5 | 无 SSR 框架时的路由：单入口 index.php + 前端控制器（解析 REQUEST_URI/PATH_INFO），Apache 靠 .htaccess rewrite（需主机允许 AllowOverride），Nginx 靠 try_files | 共享主机改不了 vhost，.htaccess 是唯一路由手段；先确认主机是否支持 | 官方文档常识（自补） |
| L6 | WordPress 生态纪律：改主题用子主题、改行为用 hook/filter，绝不改 core 与第三方插件源码（升级即覆盖） | "开发"语境部分转写为"配置+钩子定制"；与海外 SaaS 档案的转写思路同构 | 官方文档常识（自补） |
| L7 | 绝不假设库/扩展可用：先查 composer.json、phpinfo、邻近文件再引依赖 | 生成的代码必须能在目标主机立即运行 | 纪律出处：汇总/软件开发/编码规约.md §2.6（样本 D"NEVER assume a library is available"的 PHP 化应用）；PHP 具体检查项为自补 |
| L8 | 主机无 Node 构建链：前端资源（打包后的 JS/CSS）须本地构建再上传产物 | 提示词包须区分"本地构建步骤"与"主机部署步骤"，不能生成依赖主机 npm 的方案 | 官方文档常识（自补） |
| L9 | 与 Next.js 路线选型对比必须进 DECISIONS（≥2 方案）：LAMP=托管便宜/生态成熟/运维简单 vs Next.js=现代 DX/SSR/需 Node 托管（VPS 或 Vercel，成本与备案面不同） | 客户不懂栈时给推荐并记录理由，不默默替客户定栈 | 范式出处：ENGINE.md B4 第 4 条、引擎/套餐/商城开发.md 技术组"写进 DECISIONS 条款"；对比内容本身为自补 |

## 3. 对问卷槽位的影响（编号建议）

- **P1 主机前置问**：技术组选 LAMP → 追加"部署在哪？共享虚拟主机 / VPS / 已有服务器"——共享主机触发 L2/L5/L8 全部降级条款；VPS 则可放宽（可装 composer/Node/队列）。
- **P2 版本锁定**：编程-通用开发.md Q3 stack 改写为追问三连：PHP 版本？MySQL 版本？有无 WordPress 等既有系统？答案写进上下文卡与规约 frontmatter globs（`**/*.php`，格式出处：汇总/软件开发/编码规约.md §4）。
- **P3 生态分叉**：P2 答"WordPress" → 商城套餐第 2/3 条（数据库/API 设计）大幅裁剪为"WooCommerce 数据模型+钩子清单"，第 5 条前台换子主题语境（L6）。
- **P4 安全注入**：编程-通用开发.md Q10 即使客户选"无附加约束"，L4 会话/上传条款也强制注入（执行 R6 缺口声明：按通用方法拼装，组装说明注明）。
- **P5 选型拦截**：客户同时要"共享主机 + 实时推送/长队列" → 当场提示矛盾（L2），建议升 VPS 或砍需求，写入 DECISIONS。

## 4. 可挂载提示词片段

**片段 A：PHP 项目结构约定块**（注入开发提示词 Rules）

```markdown
技术栈：PHP {{8.x}} + MySQL {{版本}}，无框架单入口架构。目录约定：
public/（index.php 入口+静态资源，唯一 Web 可达目录）、src/（业务类，
按 PSR-4 组织）、templates/（视图）、config/（配置，未纳入版本库的
config.local.php 存密钥）。路由集中在 public/index.php 前端控制器分发，
禁止散落的独立可达 PHP 页。数据库访问统一 PDO 预处理语句，禁止拼接 SQL。
改动边界与命名/验证纪律照 汇总/软件开发/编码规约.md §4 骨架执行。
```

**片段 B：共享主机部署注意块**（注入部署/上线提示词）

```markdown
目标环境为共享虚拟主机：无 SSH、无 composer、无 Node、不可改 vhost。
部署产物 = 本地构建完成的整目录（含 vendor/ 与前端打包产物），FTP/面板上传。
路由重写只写 .htaccess；定时任务用主机面板 cron 触发 PHP 脚本，不假设
常驻进程。上传目录配置禁止执行脚本；数据库连接参数走 config.local.php，
绝不提交密钥（纪律参照 汇总/软件开发/Agent系统提示词.md §3 样本E 数据安全节）。
上线前用 phpinfo 核实 PHP 版本与扩展清单，逐项对照本项目依赖。
```

**片段 C：安全基线块**（注入 Q10/P4，⚠️ 自补拼装非现成规约）

```markdown
所有外部输入（GET/POST/COOKIE/上传文件名）一律校验后使用；SQL 只用预处理；
输出到 HTML 统一转义防 XSS；上传走白名单+重命名+禁执行目录；登录成功
session_regenerate_id；密码 password_hash/password_verify；表单与状态变更
接口带 CSRF token。以上为最低基线，不因"小项目"豁免。
```

## 5. [人办]与合规事项（进方案 §3 自办清单）

- 主机购买/确认：向主机商核实 PHP 版本、扩展清单、有无 SSH/composer、.htaccess 权限、cron 配额（L1/L2/L5 全部依赖此步）。
- 域名购买与解析；服务器在中国大陆则 ICP 备案 + 公安备案（周期以周计）。
- SSL 证书申请与主机面板启用（登录/支付页 HTTPS 必须）。
- 数据库账号创建与最小权限授予；确认主机自动备份策略，无则自办定期导出。
- WordPress 路线：付费主题/插件的许可证购买与续费责任归属确认。

## 6. 缺口与待核实

- **库内 PHP 素材为零**：WordPress/Laravel/安全编码/测试编写均无收集范本（安全与测试缺口与 汇总/软件开发/编码规约.md §6 一致），本档案全部片段为自补，建议后续补采 PHP 规约素材回流。
