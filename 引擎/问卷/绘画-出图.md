## 兼容规则表（选择时当场执行，不只体现在选项上）

- **R1 平台决定语法（权重写法跨平台必须换算）**：词库与写法不互通——MJ 里 Danbooru 标签（1girl 等）基本无效，走"主体+修饰词+参数尾缀"（Midjourney提示词.md §5）；SD/NAI 走标签串+正反两块。换算表（标签体系与咒语.md §2.3、SD提示词方法论.md §4.5）：
  | 意图 | SD (WebUI) | NAI v4 | NAI v5 |
  |---|---|---|---|
  | 增强 | `(tag:1.2)`（每层括号 ×1.1） | `{tag}`（每层 ×1.05） | `1.2::tag::`（不闭合 `::` 会作用到结尾所有 tag） |
  | 弱化 | `(tag:0.8)` / `[tag]` | `[tag]`（÷1.05，≈WebUI `(tag:0.952)`） | `0.5::tag::` |
  | 移除 | 写进 Negative Prompt | UC 栏 | `-1::tag::`（可加深到 -3） |
  元素法典等 SD 权重整串跨到 NAI 须逐词换算；画师名以数字结尾时（`na_tarapisu153`）会被误解析为权重，须写成 `na_tarapisu153, ::`。
- **R2 交付形态分叉**：Q1=MJ → 一条 prompt + `--ar --v --stylize --niji --no` 参数尾缀，无负向栏（排除全走 `--no`）；Q1=SD/NAI → 正向块+Negative/UC 块分离；Q1=NAI v5 → 按 §4.2 分字段交付（Base Prompt / Character 栏 / `<style>` `<artist>` 块 / UC），主串不写质量词（官网开关自动追加）。
- **R3 SD 出图差→诊断路由**：客户反馈画坏了，不按空词重抽，路由 SD提示词方法论.md §2.6 噪声诊断表（粗糙→+steps；波浪→降权；纸片混实景→查分类/风格/次元三类冲突 §2.3）与 §2.1 的 75 token 截断原理（正向串过长先砍次要 filters，或开 comma padding、提 steps）。
- **R4 "某画师风格"**：MJ 用 `Painting By {name}`，NAI/SD 用 artist tag；但在世画师名有商标/伦理争议且部分平台已限制——**商用交付默认转写为"流派+媒介+技法细节"描述**（如"新艺术风+水彩+柔化渗色边缘"），画师串仅当客户坚持且非商用时保留，规则出自画风词表.md §4.4/§5；NAI v5 画师串必须有用户给定来源，"名单不是配方"。⚠️ v5 已验证画师串库素材缺失。
- **R5 IP 角色版权边界**：Q3 涉及既有作品角色——个人练习用 Danbooru 规范英文名触发默认外观（`archetto (arknights)` 式，不用中文名）；**商用交付明确提示侵权风险**，建议改原创角色并逐项写外貌锚点；`cosplay`、`style parody` 等标签同样涉既有 IP；R18 内容默认过滤 restricted 标签（标签体系与咒语.md §5）。
- **R6 表情包/贴纸**：正方形小尺寸、扁平化，不强求质量词（sticker 配 masterpiece 是分类冲突，反向利用数据簇）；配方用 SD提示词方法论.md 样本 3（`1girl, sticker, Chibi, white background` + 负向加 `3D`）。
- **R7 立绘/设定图**：加 `character chart / three sided view` 类版式标签（构图与分镜.md 样本 5）；⚠️ SD ControlNet/LoRA 姿势控制素材为零，只有文字方案，客户要精确骨架控制需另行说明能力边界。
- **R8 图内文字（封面带标题）**：NAI v5 把要画的字原样进双引号+载体句，并关质量词开关（其 `no text` 会压字）；MJ 文字渲染不可靠，建议文字后期排版、提示词只留标题区构图空间。
- **R9 漫画页**：路由 构图与分镜.md §4.3-4.4（逐格分镜→NAI v5 Character 框容器导出），UC 预设换 Light/None（Heavy 会压掉分格），人数按身份去重。
- **R10 国风画风**：⚠️ 工笔/写意/青绿山水/敦煌的系统词表素材缺失，仅 sumi-e/nihonga/Chinese Painting 数词可用，按描述性短语组装并标 `[假设]`。
- **R11 质量词与数据簇相对性**：masterpiece/best quality 只服务"高质量数据簇"，不是万能加分项——贴纸/像素画/素描风应移除（分类冲突），Q4 选这些风格时自动改 quality 段；选词按 post_count 排序，高频标签(>10万帖)稳、低频(<1000帖)需实测或降权（标签体系与咒语.md §4.4）。
- **R12 词序即优先级**：越靠前越锚定主体与色彩分布（SD/NAI 与 MJ 通用惯例）——主体与最重要风格词放最前，光照/色彩/相机等修饰放中后段；客户想"改风格不改人"时只动后段，不重排前段。
- **R13 参考图能力边界**：客户提"保持这个角色一致/参考这张图"→ MJ 的 `--sref/--cref` 与 SD 的 ControlNet/LoRA 在本素材库均无实测资料（Midjourney提示词.md §6、SD提示词方法论.md §6），如实告知并按文字锚点方案（逐项写外貌特征）替代，标 `[假设]`。

## 终态核对（念给客户确认后再组装）

输出槽位汇总表：platform / what / subject / style / composition / light_color / negative / params / count / commercial + 所有 `[假设]` 项，客户确认或改选（改选即回跳对应题并重跑兼容检查）。

## 终态 → 组装（交回模式 A 第 3-7 步）

按 platform 选骨架，其余槽位填入：
1. **MJ**：Midjourney提示词.md §4.4 四选一组装模板（写实照片/风格插画/Niji 动漫/概念抽象）+ §4.2 精选词库取光照/相机/媒介/色彩词，同族强度词只选一档、词序即权重；动漫题材整体走 `--niji` + Niji 6 页词表（kawaii/fairycore 等核系词在 Niji 效果显著）。
2. **SD**：§4.1 五段骨架（quality→subject+style→action/scene→artist→filters）+ 负向串（低质量+人体+水印+本图定向排除）+ 参数行（steps 20-30、CFG 5-11、尺寸按类别、seed -1 探索）+ 三冲突/token 自查；CFG 语义提示客户：越高越贴词越死板（手电筒光束比喻）。
3. **NAI**：v4 用标签体系与咒语.md §4.1 通用骨架+官方排除串；v5 用 §4.2 分字段完整交付模板（Base Prompt/Character 栏/style/artist/UC），外貌不两处重复、人数 tag 只在主串开头一次、叙事句不加引号。
4. **词表引用**：画风三层（流派×媒介×画师）按 画风词表.md §4.1 槽位模板填；MJ 侧全量词回源查 27 维度分类页，本引擎只用精选池。
5. 备注：目标模型/版本、权重换算提示、迭代契约（局改只动指定范围、逐字保留原串，连带改动只列不改）。
6. 交付后跟进项：V4 时代词表在 V6+/v5 可能失效，效果不符预期回到 R3 诊断路径，不盲目重抽。
