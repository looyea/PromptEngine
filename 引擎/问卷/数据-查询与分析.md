# 问卷：数据 · 查询与分析（text-to-SQL / 探索分析 / 清洗 / 报告）

> 用途：引擎模式 B1 的访谈脚本。问完→汇总槽位确认→走模式 A 组装；方言与 schema 是两个"缺了就不生成"的硬槽位。
> 组装原料：汇总/数据/text-to-SQL.md（§4.1 主骨架、§4.2-4.6 解释/优化/纠错/迁移/格式化）、汇总/数据/数据分析与科学.md（§4.1 通用分析、4.2 建模、4.4 AB 测试、4.5 受众分层、4.6 排障、4.7 质检断言、4.8 轻量提取）。
> 访谈纪律（ENGINE.md B1）：一轮 1-3 题；客户可能不懂"方言/口径/join"这类行话，每题配一句人话解释；可说"都用默认"——但 Q2/Q3 不允许默认（见 R1/R2）。

| Q3 | 数据库方言与版本？（不同数据库 SQL 语法不通用，如同不同方言） | **PostgreSQL（注明版本，如 14）** / MySQL / SQLite / SQL Server / Oracle / Spark SQL；Python 分析则填 pandas/库版本 | dialect | 必填槽位——"不写方言是常见失败模式"（text-to-SQL.md §5）；跨方言迁移→用 §4.5 迁移骨架（要求逐一列差异点、无法等价处显式标注） |

| Q5 | 口径与时间范围？（"近 30 天"含不含今天、按时区哪一天、退货算不算销量这类规则） | 明确给：时间窗与时区 / 状态过滤（status 枚举含义） / 去重与空值约定 / **都按行业惯例并逐条标 `[假设]`** | semantics | 写进骨架的"枚举值/业务口径说明"槽（text-to-SQL.md §4.1）；⚠️ 素材无中文业务口径/中文列名先例（§6），措辞自拟并建议客户复核 |

| Q7 | 只读还是要写？ | **只读 SELECT（只看数）** / 需要 UPDATE/DELETE/INSERT（改数） / 需要建表改表（DDL） | write_access | 写操作与 DDL → 强制 R2 人审条款 |
| Q8 | 涉不涉及真实敏感数据？ | 脱敏后/仅结构（推荐） / **含真实业务数据** / 纯虚构样例 | privacy | 含真实数据 → 注入脱敏与最小化提示（数据分析与科学.md §5：素材全部缺此条款，引擎默认追加） |

## 兼容规则表（选择时当场执行，不只体现在选项上）

- **R1 无 DDL 拦截（幻觉防护）**：Q2=都没有 → 拒绝直接生成 SQL，先向客户要 DDL 或至少"表名+列名+业务含义+join 关系"；组装出的提示词必含两条：`只使用 schema 中出现的表/列，绝不发明标识符` + 拒答出口 `无法回答时返回 'I do not know'`（text-to-SQL.md §4.1/§2.2——给模型合法出口比放任编造列名更安全）。
- **R2 写操作强制人审**：Q7≠只读 → 不注入 §4.1 可选的"仅生成 SELECT"只读约束，改为写操作门：生成语句+先用同条件 SELECT 预估影响行数+显式"执行前必须 DBA/负责人批准"段；⚠️ 素材无数据安全（脱敏/行级权限/审计）条款范本，此安全段为引擎自补（text-to-SQL.md §6 明示"引擎需补默认安全段"）。
- **R3 复杂度联动推理技术**：Q6=快速看看 → zero-shot，§4.1 主骨架裸用不加戏；Q6=复杂归因 → 分步 CoT（先拆子问题再合成 SQL）+ 2-5 条同方言 few-shot，高可靠要求注明多次采样核对（ENGINE.md 第 4 步选配表 + text-to-SQL.md §5 ratio/join 弱项追加建议）。
- **R4 清洗/质检→断言而非口头判断**：Q1=清洗 → 用 数据分析与科学.md §4.7"把数据质检转化为可执行断言"骨架（非空/唯一/值域/参照完整性/分布漂移，输出违规行数与样例，全过打印 PASS），叠加 §4.6 期望-实际-环境排障式处理脏数据代码。
- **R5 报告/结论缺口**：Q1=报告 或 Q4=结论文本 → ⚠️ 无"从图表到管理层结论故事线"的报告叙事模板，可视化仅有画图代码、无图表选型/配色/误读防范（数据分析与科学.md §6）→ 用 §4.5 受众分层骨架（业务干系人档：只讲影响与决策含义、禁术语、用类比、限句数）拼装并声明通用兜底；结论一律要求"数据+口径+置信度"三件套，因果措辞谨慎（§6 统计严谨性护栏缺口）。
- **R6 建模时序防泄漏**：Q1=建模 且时序数据 → §4.2 骨架中"按时间切分 train/valid，禁止随机切分"为硬条款；特征工程建议逐条过"泄漏风险检查（是否用到未来信息/目标代理变量）"（§4.3）；关键统计计算要求展示公式与假设或直接交代码执行——`act as a statistician` 不保证统计严谨（§5"角色≠能力"）。
- **R7 无执行闭环**：⚠️ 素材无"生成→执行→报错→自修正"loop 模板（text-to-SQL.md §6）→ 不承诺自动修到跑通；用户回报错误时用 §4.4 纠错骨架（期望行为+方言版本+报错三要素），多轮极简反馈式"你上面的代码错了，[具体错在哪]，请重试"（数据分析与科学.md §3.4）。
- **R8 歧义在访谈阶段消掉**：⚠️ 无多轮澄清模板（text-to-SQL.md §6）→ 口径歧义由本问卷 Q5 当场问清，不留给模型反问；用户问题在提示词中双写（Task 段与 Answer 段各一次，防长 schema 淹没问题）并包 [QUESTION] 标签防指令注入（§2.4/§5 注入面）。
- **R9 大 schema 裁剪**：⚠️ 无"只注入相关表"策略素材（text-to-SQL.md §6）→ 表多于 ~15 张时人工挑选相关表注入，并在组装说明标 `[假设：已裁剪无关表]`。
- **R10 模板与模型耦合提示**：§4.1 极简四段式源自微调模型 SQLCoder 的训练分布——套通用大模型时 Instructions 必须扩充（只读约束/输出格式/口径约定），否则拒答与纯 SQL 输出行为不稳定（text-to-SQL.md §5）；sqlcoder 代码 Apache-2.0 可借结构，Data-Science-Prompts 未声明许可证只改写不搬运（§5 许可证注）。
