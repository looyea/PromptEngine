# 套餐：数据 · 分析项目（从"给我一个分析项目"到报告/周期性数据产品）

> 用途：引擎模式 B2 的套餐脚本。面向**一个完整分析项目**而非单条查询（单条 SQL 走 引擎/问卷/数据-查询与分析.md B1 即可）。一次业务对象访谈 → 共享 DATA_CARD → 交付 5-6 条按阶段排列的提示词（提示词包本身就是交付物：客户逐条喂给 LLM/编码 agent，产出口径确认书/质检代码/分析代码/图表/分析报告，周期性项目再加调度与监控）。
> 骨架来源：汇总/数据/text-to-SQL.md（§4.1 主骨架/拒答条款/方言槽位）、汇总/数据/数据分析与科学.md（§4.1 通用分析、§4.2 建模、§4.4 AB 测试、§4.5 受众分层、§4.6 排障、§4.7 质检断言）；R 规则继承 引擎/问卷/数据-查询与分析.md（R1-R10）。
> 阶段链（ENGINE.md 模式 B 默认链的行业裁剪）：**需求与口径确认 → 数据获取与质量检查 → 分析建模 → 可视化 → 报告叙事 →（周期性则加）自动化与监控**。需求收集=口径确认；设计+实现=取数/建模/可视化；测试=质检断言；上线=报告交付；运维=调度监控（一次性项目删末段）。
> 硬规格锚：本域没有现成的 游戏Spec01.md 级完备范例，完备度标尺固化为「硬规格锚」一节（位于文末「交付形态」之前）——DATA_CARD 与 5-6 条提示词成品逐维度对表走查，缺项不得交付（ENGINE.md 规格饱满模块第 4 条）。

## 第一阶段：业务对象问卷（逐项形成 DATA_CARD）

| 组 | 问题 | 选项（推荐值加粗） | 联动/兼容规则 |
|---|---|---|---|
| 问题 | 要回答什么业务问题？（一句人话，如"哪个渠道的退货率在恶化"） | 自由描述，**拆成 1 个主问题 + 2-4 个子问题** | 主问题写进卡首行；比率/归因/多表对比类 → R3 复杂档（CoT+few-shot，ratio 与 join 是已知易错类） |
| 数据 | 数据在哪？（DDL=建表语句，告诉模型你有哪些表和列） | **库表（有完整 DDL 含列注释）** / 只有表名零星字段 / CSV 或样本行可贴 / 都没有 | 都没有 → **R1 先拦截要材料，不许直接生成**；库表 → 追问 join 关系与方言；CSV → 走 Python/pandas 路线；>15 张表 → R9 人工裁剪相关表 |
| 数据 | 数据库方言与版本？（不同数据库 SQL 语法不通用） | **PostgreSQL（注明版本）** / MySQL / SQLite / SQL Server / Oracle / Spark SQL；CSV 路线填 pandas/库版本 | 必填硬槽位——"不写方言是常见失败模式"（text-to-SQL.md §5）；跨方言 → §4.5 迁移骨架 |
| 口径 | 口径与时间范围？（"近 30 天"含不含今天、退货算不算销量） | 明确给：时间窗与时区 / status 枚举含义 / 去重与空值约定 / **都按行业惯例并逐条标 `[假设]`** | 写进卡与骨架"业务口径说明"槽；⚠️ 无中文业务口径/中文列名先例（text-to-SQL.md §6），措辞自拟并请客户复核；歧义在访谈当场消掉（R8），不留给模型反问 |
| 交付 | 结果要什么形态？ | 可执行 SQL / Python 代码+结果解读 / 图表 / **分析报告（给业务方）** / 组合 | SQL → [SQL] 前缀+拒答条款；报告 → #5 叙事段（⚠️ R5 缺口兜底）；图表 → #4（⚠️ 仅画图代码骨架） |
| 受众 | 给谁看？ | 数据同行（可含代码与推导）/ **业务干系人（只讲影响与决策含义）** / 管理层（结论先行）/ 混合双版本 | 受众即参数（数据分析与科学.md §4.5）：业务档禁术语、用类比、限句数；结论一律"数据+口径+置信度"三件套 |
| 频率 | 一次性还是周期性？ | **一次性分析** / 周期性（周报/月报/日更看板） | 周期性 → **追加 #6 调度与监控提示词**，阶段链加"自动化与监控"段；一次性 → 删 #6 |
| 读写 | 只读还是要写？ | **只读 SELECT/只读文件（只看数）** / 需要 UPDATE/DELETE/INSERT / 需要建表改表（DDL） | 写操作与 DDL → **R2 强制人审门**：生成语句+同条件 SELECT 预估影响行数+"执行前必须 DBA/负责人批准"段 |
| 隐私 | 涉及真实敏感数据？ | **脱敏后/仅结构（推荐）** / 含真实业务数据 / 纯虚构样例 | 真实数据 → 注入脱敏与最小化提示（数据分析与科学.md §5：素材全缺此条款，引擎默认追加） |
| 方法论 | 项目怎么推进、阶段门什么形态？ | **看板（一次性探索分析，推荐）** / Scrum（周期性数据产品）/ 瀑布（审计/合规类一次性报告）/ 里程碑式（多报告大项目） | 决定阶段门形态，见下节；**任何方法论都不豁免 R1 材料拦截与 R2 写操作人审** |

### 方法论与阶段门（ENGINE.md 模式 B 方法论槽位）

- **看板（推荐，一次性探索）**：分析任务卡沿"口径→取数→建模→可视化→报告"流动；探索中发现口径问题随时回卡首列重确认，不设死板签字；每列出口=对应阶段门判据。
- **Scrum（周期性数据产品）**：每冲刺交付一个可用报告迭代（新增指标/改口径/修图表），冲刺回顾门=业务方验收+口径变更登记进卡；#6 调度上线后进入持续运维节奏。
- **瀑布（审计/合规类）**：口径确认书客户签字后才取数，报告终稿签核后交付；适合结论要对外负责的场合。
- **里程碑式（大项目）**：M0 口径定稿 → M1 数据质量达标 → M2 首版报告 → M3 自动化上线（周期性时）。

执行注（每条提示词组装时逐项落实）：

- 每条提示词开头携带完整 DATA_CARD；用户问题包 [QUESTION] 标签并双写（Task 段与 Answer 段各一次，防长 schema 淹没问题与指令注入，R8）。
- SQL 输出保留拒答出口与 [SQL] 前缀引导；附低温度/beam 解码建议与后处理约定（按 `;` 与 ``` 截断、补分号）——生产效果一半在模板一半在解码（text-to-SQL.md §2.7）。
- SQLCoder 极简四段式源自微调模型训练分布，套通用大模型必须扩充 Instructions（只读约束/输出格式/口径约定），否则拒答与纯 SQL 输出行为不稳定（R10）。
- 多文件产物注入 ENGINE.md"文件写入与产物约定"模块（产物清单/DECISIONS/PROGRESS/写入权限随 autonomy 槽位）。
- 许可证纪律：sqlcoder 代码 Apache-2.0 可借结构（模型权重 CC BY-SA 4.0 不碰）；Data-Science-Prompts 与 quickref 未声明许可证——只改写重组不逐字搬运，保留 credit 署名惯例。

## 分支裁剪（按交付形态与数据源，访谈时当场定）

- **只要一条可执行 SQL**：不属本套餐——回 引擎/问卷/数据-查询与分析.md 走 B1 单件引导；本套餐最小交付=#1/#2（口径+取数+质检）。
- **CSV/样本路线**：#2 起跳过 SQL 骨架，改 pandas 加载+§4.7 断言；方言槽填库版本；无 join 问题但有列名/类型/业务含义核对。
- **建模项目**：#3 换 数据分析与科学.md §4.2 建模骨架（数据检查→切分→基线+可选 AutoML→评估）+ §4.3 特征工程（每个特征给业务动机/构造代码/泄漏风险检查）；指标显式化（AUC/RMSE 等写进卡）。
- **AB 测试设计**：#3 换 §4.4 骨架：分流单元与比例、样本量计算（展示 α/power/MDE 假设）、实验时长、统计检验及前提检查、陷阱清单（辛普森悖论/新奇效应/多重比较）。
- **周期性看板**：#6 必追加，且 #4 图表代码须参数化（时间窗随调度滚动）；监控断言复用 #2 质检规则加分布漂移项。

## 默认速配（客户说"都用默认"时的终态，仍须念回确认）

```
问题=客户原话拆主/子问题 | 数据源与方言=不可默认（R1 拦截要材料；方言必填）
口径=行业惯例逐条标[假设] | 交付=分析报告+图表 | 受众=业务干系人
频率=一次性（删#6） | 读写=只读 | 隐私=建议脱敏 | 方法论=看板
```

数据源/方言/口径三项没有"默认"可给——缺材料就停在访谈，这是本套餐与"直接出 SQL"的分界线。

## 兼容规则汇总（访谈时当场执行，继承 引擎/问卷/数据-查询与分析.md）

- R1 无 DDL/样本拦截：材料缺失 → 拒绝直接生成，先要 DDL 或"表名+列名+业务含义+join 关系"；所有 SQL 提示词必含"绝不发明标识符"+拒答出口 'I do not know'。
- R2 写操作强制人审：非只读 → 生成语句+同条件 SELECT 预估影响行数+DBA/负责人批准段；⚠️ 脱敏/行级权限/审计条款为引擎自补（text-to-SQL.md §6 明示"引擎需补默认安全段"）。
- R3 复杂度联动：单表筛选聚合 → zero-shot；比率/多表 join/窗口/多步对比 → 分步 CoT+2-5 条同方言 few-shot，高可靠注明多次采样核对。
- R4 质检=断言：数据质量一律转化为可执行断言（§4.7），不让模型口头判断"数据没问题"。
- R5 报告叙事缺口：⚠️ 无报告叙事模板与图表选型/配色/误读防范素材 → §4.5 受众分层兜底并声明；结论强制"数据+口径+置信度"三件套。
- R6 建模防泄漏：时序按时间切分为硬条款；特征工程逐条过泄漏风险检查；`act as a statistician` 不保证统计严谨（§5"角色≠能力"）。
- R7 无执行闭环：⚠️ 不承诺自动修到跑通；报错用 §4.4/§4.6 期望-实际-环境三要素纠错，多轮极简反馈式重试。
- R8 歧义前置消解：口径歧义访谈当场问清；问题双写+[QUESTION] 标签防注入。
- R9 大 schema 裁剪：⚠️ 无"只注入相关表"策略素材 → >15 张表人工挑选，标 `[假设：已裁剪无关表]`。
- R10 许可证与耦合：SQLCoder 极简模板套通用大模型必须扩充 Instructions；未声明许可证素材只改写不搬运。
- 追加（本套餐）：周期性 → #6 必追加且首期人工核对；⚠️ 无数据治理（血缘/质量规则体系）与 agent 式分析素材、无中文报告场景先例（数据分析与科学.md §6）→ 涉及时声明通用兜底。

## 硬规格锚（本域的 游戏Spec01 位：完备交付物应长什么样）

## 交付形态

【DATA_CARD】+【5-6 条提示词（编号+用途+使用顺序）】+【阶段门清单（口径确认/质检 PASS/人审门）】。两种消费模式：

- **站内引导执行**：引擎按问卷访谈（材料缺失当场拦截）→ 生成卡 → 逐条组装，客户站内执行并贴回产物，引擎按阶段门核验放行；阶段状态与口径变更登记随卡持久化，中断续跑。
- **导出方案给客户内部团队**：按 引擎/方案模板.md（B4）生成完整方案——卡进 §4，提示词包逐条成 P 节点，阶段门进 §5；[人办] 清单必含：提供 DDL/样本与 join 关系、口径签字、DBA 写操作批准、敏感数据脱敏；§7 部署与运维映射为数据产品运维（周期性项目：调度/监控告警/口径漂移巡检/数据备份/成本账；一次性项目：产物归档与复跑说明）。缺 §7 不得交付（方案模板使用纪律第 5 条）。

客户改版/复购：改卡 → 只重跑受影响条目（改口径 → #1 起全链；只换图表 → #4/#5；新增子问题 → #3 起局部重跑）。
