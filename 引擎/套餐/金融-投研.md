## 阶段链总览（默认链的行业裁剪）

```
研究框架与问题清单(#1) → 数据收集与核实(#2) → 核心分析(#3，按类型路由)
→ 假设日志与失效条件(#4) → 备忘录成稿(#5) → 复核与归档(#6)
→ [周期性研究] 监控更新(#7，按复核日期循环，触发失效条件则回 #3)
```

- 对应 ENGINE.md 模式 B 默认链：需求收集=#1，产品/业务文档=#2/#4，设计+实现=#3/#5，测试=#3/#5 内嵌 QC 门，上线=对外发布（过 #6 合规门），运维=#7 监控与归档反哺。
- 阶段门形态随方法论槽位：里程碑式（推荐）=每阶段客户/分析师签字；瀑布=全链一次终审（不推荐，复核纪律要求分段停）；看板=#7 监控列持续流动；Scrum=多标的并行时每冲刺回顾门。
- 阶段状态随 RESEARCH_CARD 持久化：每过一门在卡上登记版本号与日期，中断后读卡从下一未完成阶段恢复（文件即记忆）。

## 阶段门失败回环（通过才进下一段）

- #1 问题不可证伪 / 口径未确认 → 回访谈"标的/类型/市场"三行，不硬产框架。
- #2 缺口影响核心结论 → 停下向客户列清单补数据；补不齐→结论降级为"条件性分析"并显式标注，不带缺口硬写。
- #3 F 类三查任一不过 → 只重跑 #3 对应节（基准混入乐观情景→拆节重算；缺失效条件→先跑 #4 再回填）。
- #4 给不出证伪条件 → 该结论退回 #3 降级或删除，不许进 #5 正文（R4 硬要求）。
- #5 QC 四查不过 → 定位是数字溯源/假设一致/口径/结论强度哪一层，只改对应层（APE 式迭代，ENGINE.md 第 7 步）。
- #6 复核签字不过 → 按复核意见回对应条目；对外合规门不过→**不发布**，改受众为内部或删个性化表述后重审。
- #7 失效条件触发 → 回 #3 重跑受影响节并升卡版本号，旧版归档留痕，不静默覆盖。

## 客户画像速查（访谈前给客户的三个典型档）

## 兼容规则汇总（访谈时当场执行，继承自 引擎/问卷/金融-投研笔记.md R1-R7）

- R1 实时与预测拒答改框架：客户要"现在该不该买/明天涨不涨/实时价/目标价"→明确拒答并说明双重边界（无实时数据+非投资建议），重新组装为分析纪律框架（CRAFT+BCE+Assumption Log+失效条件与监控指标）。
- R2 数据缺口禁编造：未提供的数字→`[数据待补]`/`[待核实]` 占位，禁止虚构财务数据与行情；QC 四查作为自检层强制注入 #3/#5/#7。
- R3 对外发布合规门：受众=对外→#6 追加合规审查门（适当性/投顾牌照边界/须持牌顾问一对一解读条款）；客户拿"机构级 prompt 原文"要求照抄→许可纪律：只借五段解剖与机制改写，不搬原文，对外分发注明方法论参考来源。
- R4 可证伪性硬要求：备忘录/论点类 Output 必含失效条件清单+监控清单+复核日期；决策只落离散矩阵，每格附触发阈值与数据源。
- R5 市场本地化：A 股/港股→欧美制度词（GIPS/Solvency II/SFDR/401k 式 IPS）全部替换为本地口径；⚠️ §6 中国市场素材为零，本地化改写未实测，逐处标 `[假设]` 并如实告知。
- R6 交易计划红线：只按 §4.6 组装（论点≤3 句；entry/stop/T1/T2 全给；**R:R<2:1 标旗拒绝**；3 KPI 证实/证伪阈值；强制退出条件），首部重申"框架演示非个性化建议"；不做实盘自动执行链路。
- R7 平台绑定剥离：素材 ch12-15 绑定 Claude 产品族——只迁移工作流思想（模型分工/成本分层/长上下文管理），不迁移产品操作细节。
