# 套餐：游戏开发（从立项到可运行成品）

> 用途：引擎模式 B2 的套餐脚本。一次业务对象访谈（游戏本体+系统清单）→ 共享上下文卡（游戏设计卡）→ 交付 7 条按里程碑排列的提示词（立项 GDD→系统设计→关卡数值→美术方案→剧本→音频→整合验收）。提示词包本身是最终交付物：客户拿着它逐条喂给编码 agent/LLM，按阶段门推进即可产出一款可运行游戏。
> 骨架来源：汇总/游戏/开发规约.md（宪法层与自主模式开关）、汇总/游戏/系统与玩法设计.md（§4 系统设计骨架）、汇总/游戏/关卡与数值设计.md（§4 数值/关卡骨架+诚实裁决）、汇总/游戏/美术.md（§4 方向+资产管线）、汇总/游戏/叙事与剧本.md（§4 全局叙事文档）、汇总/游戏/音乐音频.md（§4 音频规格与事件接线）、汇总/游戏/工作流与验收.md（§4 阶段门/证据分级/会话检查点）；链结构方法论见 汇总/软件开发/Spec驱动开发.md（specify→plan→tasks→implement 与替代路线）。
> 单件衔接：客户只想问一件（如"帮我把这个玩法想清楚"）→ 走 引擎/问卷/游戏-开发立项.md（B1），其终态判定"完整可通关"即路由回本套餐。
> **mega-spec 单文件替代路线**：客户不想跑链条、要"一次无人值守生成整款游戏"→ 不交付本套餐，改产一条超长规格提示词——结构照项目根 游戏Spec01.md（角色→工作原则→技术选型→各子系统硬规格→里程碑 M0-M5→验收清单），方法论依据 汇总/软件开发/Spec驱动开发.md §4"替代路线：单条 mega-spec"与 汇总/游戏/开发规约.md §5（无人值守边界）。访谈仍跑第一阶段，产物从"7 条链"换成"1 条 spec + 卡"（完备度按 ENGINE.md 规格饱满模块：每节硬数值+枚举清单+可判是/否验收项）。

## 第一阶段：业务对象问卷 · 上半（游戏本体）

| 组 | 问题 | 选项（推荐值加粗） | 联动/兼容规则 |
|---|---|---|---|

| 系统 | 核心玩法系统清单？ | 逐项勾选：战斗 / 成长(等级·装备·加点) / 经济 / 技能 / 敌方 AI / 存档 / 营地菜单 / 大地图 | 每项登记进卡"系统表"并标里程碑归属；战斗类必问 TTK/TTC 锚定目标——其余数值由此推导（关卡与数值设计.md §2.9）；经济必问 faucet/sink 闭环（sink 问题未解决=还没平衡，§2.8） |

## 阶段门失败回环（通过才进下一阶段）

- #1 支柱确认不过 → 回访谈重谈"类型/支柱"两行，其余不动。
- #2 规则含糊 → 该系统回 #2 单跑；发现支柱挂不上 → 移入不做清单并通知客户。
- #3 报 NOT ASSESSED → 按点名的缺项回 #2 或补客户数据，不带缺口硬出数值表。
- #4 视觉评估不过 → 按 美术.md §4.5 管线走"编辑/重生成→再评估"，两轮不过升级客户拍板取舍。
- #5 字数/时长不达标或矛盾检查失败 → 只回改受影响场景节（增量写文件，不重谈已批准节）。
- #6 触发链听辨缺失 → 回事件映射表补接线，不动规格本身。
- #7 任一项未 OBSERVED → 记入"未能验证项"清单回环修复，禁止以"读源码确认"替代观察。

## 兼容规则汇总（访谈时当场执行）

- **R1 战棋/策略类→规则追加题**：必问高低差（跳跃力/高打低命中伤害加成/弓射程随高度差且被障碍挡）与行动序类型（WT 独立行动条显示 vs 双方轮流），规格化写法参照 游戏Spec01.md §4.1-4.3；客户答不出→给该样例为默认并标 `[假设]`。
- **R2 像素/统一风格→素材获取路径联动**：选像素/HD-2D 即追问获取路径（联网抓素材 vs 程序生成）；风格对不上时**宁可统一调色板自己生成，也不拼风格不一致的素材**（美术.md §2.1）；⚠️ 像素美术专门管线（调色板管理/逐帧动画/tile 集/9-slice）无成体系提示词素材（美术.md §6），#4 按通用骨架组装并如实标注缺口。
- **R3 借鉴与抄袭边界**：系统可借鉴《皇家骑士团》式架构，但角色名/地名/台词/旋律与原始素材一律禁用，只借鉴系统与风格（开发规约.md §4、系统与玩法设计.md §5）；参考游戏"取其方向品质、避其具体表达"（美术.md 样本 B）；第三方素材逐条 CREDITS，CC0/CC-BY/OFL 优先。
- **R4 无人值守→DECISIONS 注入**：运行模式=无人值守时，每条提示词强制注入"自主决策并写进 DECISIONS.md/最终报告、遇到不确定不停下、绝不只交计划"条款（开发规约.md 样本 D/E、游戏Spec01.md 工作原则 1）；与协作式"写前必问"互斥（§5）。
- **R5 中文/本地化工程**：全量文本字体缺字扫描脚本为必交付项（游戏Spec01.md 第三节）；⚠️ 中文本地化工程规约（文本外置/占位符规范/缺字治理）无独立素材范本（开发规约.md §6、叙事与剧本.md §6），按 Spec01 零散要求+汇总/软件开发/编码规约.md 惯例组装并标注。
- **R6 Roguelike/程序化生成**：⚠️ PCG 设计规格、可通关性约束、种子复现均无成品素材（系统与玩法设计.md §6、关卡与数值设计.md §6）——此类需求降档：按通用骨架生成+建议补采素材，不承诺"完整管线"。
- **R7 多人/网络同步**：⚠️ 权威性划分/回滚/同步策略既无设计提示词也无规约范本（开发规约.md §6、系统与玩法设计.md §6），默认拒绝组装，建议单玩家模式或另找专门资料。
- **R8 平台打包/发行**：⚠️ CI/CD、商店提交、day-one patch 自动化无管线素材（工作流与验收.md §6），#7 交付止于"可运行构建+README"。
- **R9 试玩与数据回收**：⚠️ playtest 协议/问卷设计、遥测反推调参无成品模板（工作流与验收.md §6、关卡与数值设计.md §6）；平衡类验证只做"数学+可执行模拟"两级，试玩环节提示客户自拟问卷。

## 使用前置（交付时随包说明）

- 客户需有能运行代码的环境（无环境则本包只产出文档链，代码环节另议）。
- 每条提示词运行时：完整粘贴 GAME_CONTEXT + 该条正文 + Input 中列明的前序产物路径/内容。
- 阶段门评审人=客户本人；"里程碑审"模式下任何门未获明确批准不得跳段（Kiro 式显式批准，见 汇总/软件开发/Spec驱动开发.md §2.7）。
- 中断续跑：让 agent 先读 PROGRESS.md/active.md 检查点，从下一未完成节恢复（ENGINE.md 文件写入模块第 3 条）。
- 改版复购：从改卡开始，只重跑受影响条目；宪章类条款（R3 边界、CREDITS、验收词表）随每次重跑自动携带。
