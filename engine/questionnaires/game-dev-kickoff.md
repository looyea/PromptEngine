# 问卷：游戏 · 开发立项（从创意到可运行游戏）

> 用途：引擎模式 B1 的访谈脚本。问完→汇总槽位确认→走模式 A 组装；终态可能路由为"单条开发提示词"或"声明应转套餐/Loop 链"。
> 组装原料：汇总/游戏/开发规约.md（§4 规约骨架）、汇总/游戏/系统与玩法设计.md（§4 系统 GDD 骨架）、汇总/游戏/工作流与验收.md（§4 阶段门/证据分级/验收清单）、汇总/游戏/叙事与剧本.md（§4 叙事骨架）；样本原型：根目录 游戏Spec01.md（六件套/里程碑/硬验收）。
> 访谈纪律（ENGINE.md B1）：一轮 1-3 题；每题给选项+推荐值+一句人话解释；客户可说"都用默认"跳到终态——但触发 ⚠️ 缺口的题不允许默认，必须解释后由客户拍板。

## 访谈题序（一轮 1-3 题，客户可说"都用默认"跳到终态）

| # | 问题 | 选项（推荐值加粗） | 槽位 | 联动 |
|---|---|---|---|---|

| Q3 | 跑在什么平台？ | **网页（浏览器即可运行）** / 桌面 / 手机 | platform | 素材偏 Web/PlayCanvas 路线；手机→执行 R4 性能预算缺口提示 |
| Q4 | 画面风格？ | 程序生成/纯代码几何形状 / **像素或简洁 2D** / HD-2D 精致风 / 3D low-poly / ASCII 终端风 | visuals | 与 Q6 素材来源联动；ASCII/纯代码最适配"零外部素材"约束（开发规约.md §1 之 ASCII 模拟游戏样本） |

| Q6 | 素材来源约束？ | **程序生成/纯代码形状（零素材）** / 免费可商用（CC0 类，逐条登记署名） / 客户提供素材 / 想购买商用素材 | assets | "商用素材未授权"→ 执行 R3 拦截；CC0/免费→ CREDITS.md 逐条记名称/作者/来源/许可证 |
| Q6b | 音乐音效怎么办？ | 原型阶段先不做 / **免费可商用曲库（登记署名）** / 客户自备 | audio | 走 CREDITS.md 合规署名（ENGINE.md 文件写入模块5）；成品级配乐属 M4 里程碑，跨域场景拆独立提示词 |
| Q7 | 你和 AI 怎么协作？ | **协作式（每步人审、写文件前批准）** / 无人值守（agent 自主决策不停顿） | autonomy | 两套边界互斥（开发规约.md §5），选"无人值守"→ 触发 R2 |
| Q8 | 数值怎么处理？ | 由 agent 定"建议范围"并可外置调参 / **复刻标杆时逐行精确转录为 shipped tuning** | tuning_strength | 对应 开发规约.md §5 的"数值规范性强度"二档措辞，写进规约条款；数值全部外置到数据文件/constants，不硬编码 |
| Q9 | 验收底线是什么？ | 能跑不崩即可 / 核心循环可玩 / **交付前逐条可观察验收清单（运行中 OBSERVED，非读源码推断）** / 清单+保留截图证据 | acceptance | Q2=完整可通关 时底线至少为第三档；证据分级表见 工作流与验收.md §4.5 |

## 兼容规则表（选择时当场执行，不只体现在选项上）

- **R1 完整+剧情联动**：Q2=完整可通关 且 Q5≥线性 → 必追 Q5b（文本量/分支数/结局数），并声明"这条问卷装不下一款完整游戏"：终态转 Loop 链（M0 设计→M1 可玩原型→M2 系统完整→M3 内容→M4 音频菜单→M5 打磨，见 工作流与验收.md §4.1；六件套 GDD/STORY/DECISIONS/PROGRESS/CREDITS/README，见 ENGINE.md 文件写入模块1）。当前 引擎/套餐/ 目录下尚无"游戏全量生产"套餐 → 按 ENGINE.md B2 第 4 条现场生成链，并建议沉淀为套餐。
- **R2 无人值守**：Q7=无人值守 → 注入条款："遇不确定自己决定并写进 DECISIONS.md 与最终报告，绝不停在计划上"（开发规约.md §3 样本D/E）；写入权限改为"直接写但全程留记录"；每个决策比较 ≥2 方案再定（ENGINE.md 文件写入模块2）；假设逐条标 `[假设]` 供事后核对。
- **R3 素材拦截**：Q6 选"商用素材"且无法证明授权 → 拦截并提示：规约边界明文"禁止使用任何商业游戏的原始素材/角色名/台词/旋律，只借鉴系统与风格"（开发规约.md §4）；改选免费可商用+署名，或程序生成。借鉴玩法机制结构可以，具体表达须原创（系统与玩法设计.md §5 的 Spec01"参考《皇家骑士团》但禁用其素材"范例）。
- **R4 手机/主机缺口**：⚠️ 素材库无移动端/主机性能预算（帧率/内存/draw call）写进规约的范本（开发规约.md §6）。客户坚持手机 → 用通用条款+自报硬指标占位，标 `[假设：性能预算由实现期实测]`，建议先做网页版验证手感。
- **R5 多人缺口**：⚠️ 无网络/多人同步（确定性、回滚、权威划分）规约素材（开发规约.md §6、系统与玩法设计.md §6）→ 强烈建议移出范围；客户坚持则拆为独立研究任务，不进本次交付。
- **R6 程序化生成缺口**：Q4=程序生成 且玩法依赖关卡随机生成 → ⚠️ 无 PCG/Roguelike 成品设计规格（系统与玩法设计.md §6），GDD 只写到规则层，随机参数留给实现并记 DECISIONS。
- **R7 教学关/UI 缺口**：⚠️ 无新手引导与 UI/UX 系统独立模板（系统与玩法设计.md §6）→ 作为系统 GDD 的普通里程碑处理，验收仍按"UI 每屏截图 BLOCKING"（工作流与验收.md §4.5）。
- **R8 引擎路线提示**：Q3 选桌面/手机且指定 Godot/Unity/Unreal → ⚠️ 素材偏 Web/PlayCanvas，引擎路线端到端工作流未经实测（工作流与验收.md §6；开发规约.md §6 缺 Unity 通用/Unreal 成体系规约）→ 组装时声明按通用规约骨架+自写引擎条款；playcanvas-prompts 仓库未声明许可证，只借鉴结构不搬运原文（开发规约.md §5）。
- **R9 rigor 降档**：Q2=单关原型 → 可 waive GDD 走一页 game-brief + 直接进规约+实现两条提示词，但"look 不 waive"（工作流与验收.md §5：视觉证据永远是 BLOCKING）。

## 终态 → 组装（交回模式 A 第 3-7 步）

1. **小需求终态**（Q2=单关原型，或只要一份"开发纪律"）→ 单条提示词：开发规约.md §4 骨架（角色→边界→文件命名→编码纪律→验收→协作模式二选一），叠加 Q1 类型的系统 GDD 简版（系统与玩法设计.md §4，可按 CCGS 降档只出 5 节）。
2. **完整游戏终态** → 不塞一条 mega-prompt：先交付上面的 GAME_BRIEF 卡，再按 R1 生成 M0-M5 提示词链，每条前缀共享规约、开头携带完整卡（同 引擎/套餐/商城开发.md 的上下文卡传递范式）。
3. 验收条款统一引用 工作流与验收.md §4.5 证据分级 + §4.6"OBSERVED 非推断、收尾诚实报告未能验证项"；长任务加 active.md 检查点条款（文件即记忆，中断后从下一未完成节恢复）。

## 交付为"生成器"时（B3）

客户想复用 → 本问卷 + 汇总/提示词方法论/结构化提示词.md §4.2 元提示词骨架合并为"游戏立项提示词生成器"。
