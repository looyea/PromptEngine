# 方案模板（B4 顾问式方案的交付骨架）

> 用途：ENGINE.md B4 第 5 步的输出模板。一份方案 = 本文档结构填实。消费者三层：客户（看懂并去办）、LLM 开发（逐节点执行提示词包）、人审（按审查门把关）。
> 各章节的"工种视角"从对应 汇总 文档拉取，路径已标注。

---

```markdown
# {{项目名}} 顾问方案
> 由提示词工程引擎 B4 生成 · {{日期}} · 版本 {{v1}}
> 阅读顺序：客户看 §0-§3+§7 白话部分；LLM 开发者看 §4 提示词包；人审看 §5 门表；运维看 §7。
> 双可读纪律：同一份方案两层表达——§0/§1/§3 全白话（禁术语），§2"要做什么"每部分先一句客户白话再列技术规格，§4/§7 面向 IT。客户和 IT 各读各的层，不互相翻译。

## 0. 执行摘要
一段客户听得懂的话：做什么、给谁用、做完能到什么效果、大概分几步、客户自己要办哪几件事、预期时间线。

## 1. 目标与验收标准
- 业务目标：{{客户话原文 + 转译}}
- 可检验结果 3-7 条（每条一个动作能验证，禁止"体验好"式空词——参照 视频生成提示词.md"展示不讲述"纪律）

## 2. 分解树
按部分分组，每行一个子部分节点：

| # | 部分 | 子部分 | 要做什么 | 要注意什么（工种会签） | 承担方 |
|---|---|---|---|---|---|
| 2.1 | {{功能/内容}} | {{…}} | {{…}} | {{技术坑/合规/数据…引用汇总}} | [LLM开发] |
| 2.2 | | | | | [人办] 例：ICP备案/支付资质/账号注册/合同签署 |
| 2.3 | | | | | [第三方] 例：短信通道/支付渠道/云主机 |

**承担方图例**：[系统]=软件功能里实现 / [LLM开发]=附提示词 / [人办]=客户真人操作（系统边界之下，软件帮不了）/ [第三方]=外部服务依赖。

## 3. 你需要自己办的事（[人办]+[第三方] 清单）
按先后排序，每项：办什么 / 在哪办 / 前置条件 / 大概周期 / 卡住哪个节点。
——本章节是方案可信度的核心：宁可啰嗦，不可漏项（备案、资质、实名、隐私政策、退款政策…按行业从对应问卷 R 规则拉）。

## 4. 提示词包（[LLM开发] 节点逐一实现）
共享 {{上下文卡}}（模板见 套餐/商城开发.md）。每条：

### P{{n}} {{节点名}}
- Input：上下文卡 + 依赖节点产物（如 P2 schema 必须先过门）
- 提示词正文：（模式 A 组装，含文件写入约定模块）
- 自检/证据：LLM 开发完成后必须产出什么（测试截图/运行命令/验收清单勾选）——参照 游戏/工作流与验收.md 证据分级
- 人审门：谁看、看什么、不通过怎么回

## 5. 里程碑与审查门
| 里程碑 | 包含节点 | 出口判据（全绿才进下一段） | 人审动作 |
|---|---|---|---|
| M0 定稿 | §1-§3 | 客户签字确认验收标准+自办清单 | 客户读一遍 |
| M1…Mn | {{…}} | {{…}} | Code Review {{关键点}} |

## 6. 风险与假设
- [假设] 访谈中默认掉的槽位，逐条列出，客户可推翻
- 风险 3-5 条：什么情况下方案要改、改哪节

## 7. 部署与运维（闭环的后半段，缺此章不得交付）
- **部署**：上线形态（托管/服务器/小程序审核）与发布流程；**CI/CD 流水线**（构建→内容/数据校验→自动测试→发布→可回滚）；上线检查单（HTTPS/政策页/备份/监控就位）；回滚预案（上一版本快照可一键回退）。
- **监控与告警**：盯什么指标（可用性/核心流程成功率/第三方 API 错误与延迟/费用）、阈值、告警给谁。
- **备份与数据**：备份对象/频率/恢复演练；用户数据最小化与删除通道（法务会签）。
- **成本账**：固定（托管/域名）+ 变动（API 按量/短信/支付手续费）；免费额度与超限动作。
- **运维节奏**：内容更新流程与频率（谁改、怎么发布）、依赖升级周期、例行巡检。
- **故障预案**：最可能坏的 2-3 处（第三方 API 挂/内容解析失败/流量超限）各给降级或回滚动作。
- **迭代闭环**：使用数据（完成率/卡点/失败样例）→ 回流 Hyper Set（问卷措辞/骨架/套餐修订）→ 再发布。运维不是终点，是下一轮裁剪的输入。
```

| 产品 | 用户是谁？主路径 3 步能走完？不做清单定了吗？ | B2B商业/产品与运营.md；Spec驱动开发.md |

| 测试验收 | 每节点证据类型定了吗？最终验收 = §1 逐条核对 | 游戏/工作流与验收.md §测试证据分级 |

## 使用纪律

1. 客户没提但工种清单会踩的坑 → 必须补进 §2 并在 §0 用一句话预告（"另需办理 X/Y，见 §3"）。
2. §3 缺一项就是一份玩具方案——[人办] 事项永远存在，找不到就说明拆解没做完。
3. 提示词包条目数 >10 时按里程碑分卷，避免一次淹没客户。
4. 医疗/金融/法律项目：方案首页顶格放该行业问卷的 ⚠️ 合规声明，§4 每条提示词重复注入。
5. **§7 缺失 = 闭环只走了一半，不得交付**。部署和运维节点同样进 §2 分解树（承担方多为 [系统]+[人办]），同样有提示词或操作清单。
6. Hyper Set 裁剪留痕：§4 组装说明注明每条提示词裁自哪篇汇总/问卷（可追溯），未命中的域声明"按通用骨架生成"。
