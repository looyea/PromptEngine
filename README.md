# 顾问系统 · 提示词工程引擎 + Hyper Set 知识库

> **你告诉它想做什么，它像高级顾问一样一步步问你，最后交给你一条能直接用的提示词、一份 Spec，或一整套"可以拿去让 AI 开发"的方案。**
> **它是什么：一套"给人用的思维链"。** 提示词技术里有 CoT（让 AI 把中间推理步骤摆出来）；本引擎干的是同一件事，只不过对象是人——把"从一句粗需求到一份完备交付"的思路替你就捋顺成固定七步，你要的内容往槽位里添就行。
> 它不是软件，没有要安装的程序：一个 markdown 文件库 + 任何一个大语言模型（DeepSeek/Kimi/ChatGPT/Claude/通义…免费额度都行），LLM 读着 `引擎/ENGINE.md` 就"变成"引擎。
> 收集自 GitHub 与各网站的 37 篇行业汇总、13 份引导问卷、8 套开发套餐、3 份平台档案 = 顾问的脑子（Hyper Set）。

---

## 你为什么要它（1 分钟）

- 直接对 AI 说"帮我写首歌"，得到的是瞎猜——它不知道你听懂不懂乐理、要多长、给谁听。
- 用本库：它先**问**你（每题带推荐值和"为什么"），冲突的选择当场拦截（选了纯音乐就不问歌词），最后成品里没有任何它替你猜的东西——猜的都标 `[假设]`。
- 需求大时反过来帮你**拆事**：要做什么/注意什么/哪些必须你自己办（备案、资质、注册账号）/哪些交给 AI 写代码，一份方案齐活，AI 开发、你只做 Code Review。

示例成品（三行看效果）：不懂音乐的人答完 7 道题，拿到 Suno 的两个字段——一段英文风格串 + 带 `[verse]/[chorus]` 元标签的中文歌词结构，粘贴即用。完整走查见文末"第一次跑起来长什么样"。

## 我们做什么、不做什么（30 秒读完，别误会）

**这个系统做的**：
- 把你一句粗需求，通过引导问答，变成**可直接执行的交付物**：一条提示词、一份 Spec、一整套方案或 Skill 包。
- 告诉你**怎么落地**：用什么工具、去哪注册、大概花多少钱、哪些事必须你自己办（备案、资质、签字）。
- 把猜的地方全标出来（`[假设]`/`[待核实]`），库里没有的知识**如实说没有**，不硬编。
- 让你**改得起**：成品不满意说人话（"太吵了""换个题材"），改参数重跑，不用抠文本。

**这个系统不做的（同样重要）**：
- ❌ **不给法律意见/医疗诊断/投资建议**——这三类的结论必须过执业律师/医生/持牌顾问的人审门，任何模式不豁免。它是帮你准备问题的顾问，不是签字的人。
- ❌ **不代执行**——它产出"给 AI 的指令"，不替你注册账号、不替你付款、不提供模型和服务器。扣扳机那一下永远在你手里。
- ❌ **不会编**——不虚构数据、引用、接口名；没实测过的平台规则会标"用前核实"。
- ❌ **没有实时能力**——不知道今天的行情、现在的热播、本周改的平台政策。
- ❌ **不承诺效果**——示例输出是示意，"律师时间降 40%"这类数字是素材作者的目标值，不是实测保证。
- ❌ **不做版权洗白**——许可证不明的来源只借结构不搬原文；歌手名、商业游戏素材一律禁用。
- ❌ **不做违法灰产**——垃圾群发、冒充、伪造、规避侦查类内容直接拒。

（这条声明本身写进了引擎 ENGINE.md v0.7：每份交付物首页必须带上它。）

**成品的长相（重要）**：交付的不是留给你填空的空模板，而是像本仓库 `游戏Spec01.md` 那样**写满具体规格的成品**——每节有硬数值（地图尺寸、BGM 首数下限、TTK 回合数）、枚举清单（选型方向、素材来源、菜单项）、能回答是/否的验收勾选框。框架性的东西我们统一规定，具体肉由引擎填到位，剩下"真正动手做"的内容交给执行它的 AI；你想自己发挥，就在这份完备成品上改。产出可以是一个总纲文件（一次无人值守跑完的中小需求），也可以是按部分拆开的多份提示词包（音乐、美术、前后端、流程各一份）——两种形态完备度下限相同（ENGINE.md v0.8 规格饱满模块）。

**引擎内部用了哪些提示词技术、用在哪**（不是空喊"有 CoT"，每一步都有指名道姓的技术撑着，ENGINE.md v0.9 第 4 步技术应用地图）：
- **组装成品时**：需要模仿特定格式→插 few-shot 示例块；要多步推导（算数/审查/设计）→尾部插 CoT 块"先列条件→分步推理→查遗漏→才下结论"；怕它编资料→插参考文本块"没提及就答未提及"；评价/审校类→把流程拆成"草拟→攻击己稿→修订"三相，质疑清单必须可见。
- **引擎自查时**：质检门用的就是自我批判（每条要证据）；改版按 APE 思路只动出问题的那一层。
- **不达标时的升级次序**：zero-shot → few-shot → CoT → 多次采样投票 → 拆任务链——逐级升，不跳级堆技术名词。

## 这和 Qoder / Claude Code / ChatGPT 这类 AI 工具到底有什么区别？

一句话：**那些是"干活的人"，本库是"当顾问的规矩"。** 它们不是竞品，是上下游。

| | Qoder 这类 agent 工具 / 直接聊天 AI | 本库（顾问系统） |
|---|---|---|
| 本质 | 软件产品：模型+工具+权限，直接读写文件、跑代码、开浏览器 | 一堆 md 文本+纪律：加载进**任何**大模型，那个模型就"变成"顾问 |
| 产出 | 直接把活干了 | 产出"给 AI 的指令"——提示词/Spec/完整方案；**扣扳机那一下在执行端**（可以是 Qoder，可以是聊天 AI，可以是外包程序员） |
| 知识 | 通用能力，没有你行业的口径 | Hyper Set：37 篇行业汇总+13 份引导问卷+8 套套餐+7 套硬规格锚——访谈时的兼容规则、合规注入、落地卡，全在库里 |
| 归属 | 绑定那家产品的订阅和生态 | 纯文本，U 盘拷走；DeepSeek/Kimi/ChatGPT/通义免费额度即可跑 |

两条链看懂关系：

- **本库在上游**：你一句粗需求 → 引擎访谈 → 交付完备 Spec（比如仓库里 `游戏Spec01.md` 那种写满数值和验收项的成品）→ 把 Spec 贴进 Qoder/Claude Code 这类工具 → 它照着开发和自测，你做 Code Review。**Spec 写得越饱满，执行机器越少瞎猜**——这就是两边合作的接口。
- **它们在本库下游，也在本库上面**：引擎不抢 agent 的活——它规定 agent 该干什么、干到什么标准、哪里必须停下来给人看（阶段门、人审门）。反过来，你也可以把问卷做成这类工具的 Skill（引擎 B5 交付形态），让它自动触发访谈。

所以别问"我已经有 Qoder 了还要这库干嘛"——正如有了施工队，还需要图纸、预算表和验收单。本库产的就是后者。

## 第 0 步 · 拿到它（新电脑，从零开始）

**方式 A：命令行**（装有 git）：
```bash
git clone https://github.com/<仓库地址>/prompt-consultant.git
cd prompt-consultant
```
**方式 B：不用命令行**：GitHub 页面绿色按钮 `Code → Download ZIP`，解压到任意文件夹。就这样。没有任何依赖：不用 npm/pip/node，库里只有 .md 文本文件，**右键用记事本就能打开每一个**。

> 最低要求只有一个：你能上网用一个聊天 AI（网页版即可），并且本库的文件在你手边（解压的文件夹）。

## 第 1 步 · 第一次跑起来（5 分钟，三条路任选）

### 路线 1：网页版 AI + 复制粘贴（零安装，推荐先试这条）

1. 打开任意一个对话式 AI 的新会话（选指令跟随强的模型；免费额度够用）。
2. 打开本库 `引擎/ENGINE.md`，**全文复制**，粘贴进对话框，前面加一行：
   > 从现在起你就是这份文档定义的提示词工程引擎，按它的规则工作。
3. 再复制 `引擎/索引.md` 粘贴过去（这是它的路由表）。发送。
4. 说人话提需求：**"我想写首歌送给女朋友，纪念三周年，我不懂音乐。"**
5. **它应该反问你先别急着生成**——这就跑通了。之后按它的题回答 2-4 轮。
6. 过程中它若说"加载 问卷/音乐-写歌.md"：打开那个文件，复制，粘贴给它即可。**用到哪份贴哪份，永远不用一次贴全库。**

### 路线 2：有文件读取能力的 AI 助手（Qoder / Claude Code / Cursor 等，最省心）

在助手对话里把本库目录设为工作目录，然后只说一句：
> 读取 引擎/ENGINE.md 和 引擎/索引.md，作为引擎工作。帮我：写一首三周年纪念歌曲的 Suno 提示词。

它自己读文件，你只管答题。

### 路线 3：不接 AI，纯手动（想学提示词原理/公司环境不让用外部 AI）

打开 `引擎/问卷/` 里对应域的问卷，按题序自己把答案写在槽位表里，照问卷末尾"终态→组装"指向的 `汇总/<域>/*.md §4` 骨架，把答案填进 `{{}}` 占位符——得到的就是成品提示词。问卷本身就是给"人肉引擎"用的模板。

## 第 2 步 · 验证引擎活了没有（ checklist）

跑起来后对照，**缺一条就说明没加载成功**：
- [ ] 它先提问，不直接生成
- [ ] 每题给推荐值和选项，而不是审讯式连问开放题
- [ ] 一轮最多 1-3 题（一次甩 10 题=没遵守 ENGINE.md）
- [ ] 有冲突时当场拦（如"lo-fi + 体育场级制作"会被质疑）
- [ ] 问完先用一张"槽位表"跟你核对，再出成品
- [ ] 它拿不准的都带 `[假设]` 标记

常见救法：换更强的模型 / 开新会话重贴 ENGINE.md 全文（被截断最常见）/ 提醒它"回到你第一条消息里的引擎规则"。

## 第 3 步 · 日常怎么用（五种姿势，由小到大）

| 你要什么 | 对它说什么 | 用什么 |

## 第 3.5 步 · 改成品像改代码：回溯修改（不抠文本）

生成的提示词就当代码看待：**你改的是参数（槽位），不是字**。每份交付物尾部自带两样东西——槽位表（它的"源代码"）和修订地图（成品每段 ← 哪个槽位 ← 哪道题），所以改版三步：

1. **照抱怨词典说一句人话**，例如音乐成品："太电子了"→乐器槽；"中段那个叮咚声去掉"→八音盒要素；"再慢点"→BPM 槽；"整体不对劲"→回去重答用途/风格/情绪三题。
2. 把 **槽位表 + 成品**一起贴回任意 AI，说："按改件规程，把 [槽位X] 改成 [Y]，只重出受影响的段。"
3. 它给你**改后的那一段**（整块替换即可，其余一字不动）+ 新版本号 v2——旧版留档，改了什么为什么改记一行。套餐类项目改的是上下文卡，卡一升版，只重跑受影响的那几条提示词。

不会用命令行也不要 git：上面这套就是"手工版 diff + 版本管理"；想更正规，就把文件夹变成 git 仓库，每个改版一次 commit。

## 第 4 步 · 执行完了，这东西还用不用？

**用。它不是跑完就废的一次性脚本，是资产：**
- **交付物**（提示词/Spec/方案 md）你自己存进项目文件夹——换任何 AI、换到 Suno/Midjourney/编码工具，纯文本到哪都能用。
- **上下文卡**（套餐模式的项目档案）留在项目里——下次改版只改卡，重跑受影响的几条提示词，不用重头访谈。
- **库本体**永远常青：纯 markdown，无服务器无依赖，U 盘拷走就能用。你的每个项目攒下的卡，就是你自己的第二层 Hyper Set。
- 建议仓库布局：本库放 `~/prompt-consultant/`，你的项目里放一个 `CONTEXT_CARD.md` + 编号提示词文件——引擎的"文件写入与产物约定模块"会引导 AI 自动这么干。

## 第 5 步 · 怎么升级

**取上游**：`git pull`（或重新下载 ZIP 覆盖）。拉完把"验证清单"再跑一遍即可，库的格式向后兼容。

**自己喂料（引擎变强的唯一途径，四步）**：
1. **收集**：看到好的提示词/仓库 → 整篇存入 `素材/github/<名>/`，照邻居文件的格式写一份 `_来源.md`（URL/许可证/日期）。
2. **汇总**：按六段结构写 `汇总/<域>/<主题>.md`（概述/共性模式/代表样本/§4 可复用骨架/§5 边界与许可证/§6 缺口）。
3. **接路由**：新域/新主题 → 更新 `引擎/索引.md` 表；要引导客户 → 照 `问卷/音乐-写歌.md` 的格式写问卷；要多阶段交付 → 照 `套餐/商城开发.md` 的范式写套餐。
4. **回流**：用的时候发现某题问得别扭、某成品不好用 → 直接改那个 md。使用中的毛病是最高优先级的升级项。

**时效注意**：平台规则（微信小程序/支付/各 AI 工具的语法）变化快——`引擎/平台档案/` 显著标注了"引擎自补，用前以官方文档核实"；素材出处与收集日期全在 `02-来源清单.md`。

## 第 6 步 · 为什么它越用越锋利：机床造机床

这套东西的正确理解方式，是**手工搓机床**：
- 一开始没有像样的工具，人拿锉刀手工搓出第一台粗糙的机床（本库的 v0.1：一条七步流水线+第一篇问卷）。
- 机床一旦能用，就用它干活、顺便**造下一台更精密的机床**——用写好的问卷格式造新问卷，用套餐范式造新套餐，用元提示词造提示词生成器，用踩过的坑改引擎规则。
- 工件不断出，机床也不断换代：v0.3 消灭了"拿到提示词不知道去哪用"这类卡点，v0.4 消灭了"交付太简略、客户看不懂"这类卡点。**每一版的版本号，记录的是它比上一版少让人卡住在哪。**
- 终点是一个理想态——"终极机床"：任何人从一句说不太明白的需求，到拿到能用的成品，全程不卡住。到不了，但每一步都更接近，而且**它的进化不靠某个天才，靠的全是使用时暴露的毛病**。

所以你报的每个毛病都不是抱怨，是锉刀："这道题问得别扭"→ 问卷改；"这段提示词没管用"→ 骨架改；"我根本不知道 Suno 是什么"→ 引擎从此强制附落地卡（这就是 v0.3 的由来）。第 5 步"喂料"的回流一条，就是这个循环的日常运转。



## FAQ

**问：对话太长贴不下了？** 分批：ENGINE.md 永远在开头，问卷/汇总按引擎点名的顺序一份份贴；或改用路线 2（文件型助手自己读，不占你的粘贴功夫）。
**问：小模型跑不动？** 引擎依赖指令跟随能力，7B 级小模型常跳题。跑不动不是你的错，换模型。
**问：敏感资料能给吗？** 先脱敏。库的法律问卷自带"输入前隐去当事方与金额"提示、医疗问卷有 PHI 条款——照它说的做。
**问：没有 Suno/某平台账号？** 问卷选平台槽位时换成你有的；骨架里平台无关的部分照用。
**问：换台机器/新开对话，引擎会不会"失忆变笨"？** 不会，这是设计出来的：引擎的全部能力只来自库里的文件（规则、骨架、教训都写在 md 里），不依赖任何 AI 的会话记忆或账号历史——这条叫"记忆外置纪律"（ENGINE.md 约束节）。判断标准很简单：如果一个经验没写进文件，它就不算存在。所以你在旧机器上踩出的坑，要么已经改进了库（R 规则/版本行里有它），要么就该由你按第 6 步"机床三问"回写。
**问：医疗/金融/法律能用吗？** 能，且库会强制提醒：非诊断/非投资建议/非法律意见，结论必须过专业人士人审——这条不可关闭，是本库的底线设计。

## 库的三层：素材 / 汇总 / 引擎——怎么使用、发布什么

一句话比喻：**素材是矿石，汇总是炼好的钢材与图纸，引擎是加工钢材的机床。用户只用机床。**

| 层 | 是什么 | 谁在用 | 什么时候用 |
|---|---|---|---|
| 引擎/ | ENGINE.md（程序）+ 索引.md（路由表）+ 问卷/套餐/平台档案/方案模板（引导脚本） | 终端用户 + LLM | 每次产出提示词/方案——你日常只接触这层 |
| 汇总/ | 37 篇行业知识汇总，每篇 §4 是可复用骨架 | 引擎（LLM 组装时读取） | 组装提示词时抽骨架、取边界条款；人不直接用 |
| 素材/ | 从 GitHub/各网站收集的原始仓库与文章，每源附 _来源.md（URL/许可证/日期） | 只有维护者 | 写/更新汇总时（喂料），或需要回查原文时；**运行引擎完全不碰它** |

数据流向：`素材 →（人工/AI 提炼，六段结构）→ 汇总 →（引擎第 2-3 步路由取骨架）→ 交付物 →（使用暴露毛病）→ 回写前三层`。素材是车间库存，不是产品零件。

**发布范围（本仓库随 GitHub 发布的内容）**：
- ✅ 发布：README、00/01/02 三份说明、`引擎/` 全部、`汇总/` 全部（自产汇总与改写，MIT）。
- ❌ 不发布：`素材/`——其中部分来源许可证未声明、网络抓取内容版权归属不清，二次分发有风险；且用户跑引擎不需要它。所有来源的 URL 与许可证已登记在 `02-来源清单.md`，任何人可按清单自行复采。落地方式：`.gitignore` 排除 `素材/`（或 git add 时逐目录点名）。
- 例外说明：素材中明确 CC0/MIT/Apache 的源本可保留署名后分发，但仓库只留链接不留副本，保持干净。
